## 1. الصورة العامة

```
┌──────────────────────────── تطبيق الجوال (Unity LTS + URP) ────────────────────────────┐
│  الواجهة RTL │ خارطة الملاعب 3D │ التجميع │ الألعاب │ المحفظة │ الموقع (Native) │ مسح QR │
└───────────────┬───────────────────────────────────────────────────────────────────────┘
                │  Firebase SDK + App Check
┌───────────────▼──────────────── Firebase / Google Cloud (مُدار بالكامل) ─────────────────┐
│ Auth (عالمي)       │ Remote Config (عالمي، محتوى عام فقط)                                │
│ Cloud Functions 2nd gen  ─ me-central2 (الدمام): كل منطق الاستحقاق والاسترداد             │
│ Firestore (Native) ─ me-central2: البيانات، والغرف، والمحافظ، والأحداث                    │
│ Cloud Tasks + Cloud Scheduler ─ me-central2 │ Secret Manager │ Crashlytics               │
└───────────────▲───────────────────────────────────────────────────────────────────────┘
                │  Callable Functions فقط
┌───────────────┴──────────── لوحة الشركاء (ويب، Firebase Hosting) ─────────────────────────┐
│ الحملات │ الفروع والمناطق │ شاشة الفرع (الرمز اليومي) │ وضع الموظف (مسح الاسترداد + رمز الفاتورة) │ التقارير │
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

**المبدأ الحاكم:** العميل يعرض ويطلب، والخادم يقرر. ما فيه أي قيمة اقتصادية تُكتب من العميل مباشرة.

## 2. العميل: Unity LTS + URP

| المكون | القرار |
|---|---|
| إصدار المحرك | أحدث Unity LTS متاح عند بداية التطوير، ويُثبت طوال الموسم |
| الرسوم | URP بإعداد الجوال: إضاءة مخبوزة (Baked)، وظل واحد ديناميكي فقط في مشهد الملعب، وبدون Post-processing ثقيل |
| النصوص العربية | TextMeshPro مع مكتبة RTLTMPro (رخصة MIT) للتشكيل والاتجاه، وخط عربي بترخيص OFL |
| مسح QR | مكتبة ZXing.Net (رخصة Apache 2.0) فوق كاميرا الجهاز |
| الموقع | إضافة أصلية (Native Plugin) صغيرة: CoreLocation في iOS بإذن When In Use و`requestLocation` لقراءة وحدة، و FusedLocationProvider في Android بطلب `getCurrentLocation` عالي الدقة مع إرجاع علامة الموقع الوهمي (`isMock`) |
| Firebase | Firebase Unity SDK: Auth، و Firestore، و Functions، و Remote Config، و App Check، و Crashlytics |
| تحميل المشاهد | مشهد Boot، ومشهد Hub يحمل لوحة المدينة إضافيًا (Additive)، ومشهد Stadium يُعاد استخدامه للمحطات الثمانية |

### 2.1 دورة قراءة الموقع (Foreground فقط)

1. حدث فتح التطبيق، أو العودة من الخلفية، أو ضغط «امسح رمز الفرع».
2. إذا الإذن غير ممنوح: ما يُطلب إلا عند أول ضغط على ميزة ميدانية، مع شرح مسبق.
3. قراءة وحدة بحد انتظار 8 ثوانٍ.
4. إرسال القراءة لـ `verifyPresence`. الخادم يحسب المسافة لكل المناطق القريبة ويحفظ **النتيجة فقط**: المنطقة، وهل قُبلت، ونطاق الدقة. **والإحداثيات ما تُخزن.**
5. ما فيه أي طلب موقع في الخلفية، ولا Region Monitoring.

### 2.2 ميزانية الأداء

| المقياس | الحد |
|---|---|
| زمن الإقلاع البارد حتى أول شاشة تفاعلية (Android متوسط، 4GB RAM) | < 5 ثوانٍ |
| معدل الإطارات على لوحة المدينة ومشهد الملعب | ≥ 30 إطارًا/ث |
| حجم التحميل الأولي | ≤ 150 MB |
| الذاكرة في الذروة | ≤ 600 MB |

## 3. عُدّة الملعب القابلة لإعادة الاستخدام

- Prefab واحد للملعب من قطع Low-poly معيارية: المدرج، والسقف، والأعمدة، والإضاءة، والأرضية.
- كل محطة من الثمانية تعريف بيانات (ScriptableObject) يحدد:
  - عدد طبقات المدرج.
  - شكل السقف (من 3 أنواع).
  - لون الإبراز.
  - لافتة الاسم (نص).
  - موضعه على لوحة المدينة.
- **النتيجة:** ثمانية ملاعب مميزة بصريًا من نموذج واحد. وما فيه أي ملعب نسخة مطابقة لمبنى حقيقي.

## 4. الخلفية: Firebase

## 6. نظام QR

### 6.1 رمز الفرع اليومي (متعدد الاستخدامات، متغير يوميًا)

- **المحتوى:** معرّف الفرع، وتاريخ اليوم في اللعبة، وتوقيع HMAC-SHA256 بمفتاح في Secret Manager.
- **التوليد:** `rotateBranchCodes` الساعة 04:00، ويُعرض في «شاشة الفرع» على جهاز الفرع (لوحي أو جوال).
- **التحقق في `scanBranchCode`:**
  1. التوقيع صحيح.
  2. التاريخ هو اليوم.
  3. الفرع نشط.
  4. ما فيه أي قفل على الرمز: نفس الرمز يقبله الخادم من أي عدد من اللاعبين في نفس الوقت.
- **التكرار:** نتيجة اللاعب الواحد مخزنة بمفتاح `uid + branchId + date`، فإعادة المسح ترجع نفس النتيجة.
- **رمز أمس أو رمز مزور:** يُرفض برسالة «الرمز غير صالح — امسح رمز اليوم في الفرع».

### 6.2 رمز الاسترداد الفردي (أحادي الاستخدام)

- يُولّد مع القسيمة عند المنح. ويحتوي:
  - رمزًا عشوائيًا بطول 128 بت داخل QR.
  - رمزًا يدويًا من 8 أحرف.
- **التخزين:** بصمة (Hash) الرمز فقط، وما يُخزن الرمز نفسه.
- **`redeemCoupon`:** معاملة وحدة تقرأ القسيمة وتشترط:
  - الحالة `issued`.
  - الصلاحية سارية.
  - فرع الموظف ضمن فروع الحملة.

  ثم تكتب `redeemed`. أي مسح ثانٍ للرمز، حتى لو متزامن، يرجع «القسيمة مستخدمة».
- **محاولات الإدخال اليدوي:** محدودة بـ 10 لكل موظف في الدقيقة.

### 6.3 رمز الفاتورة

- 6 أحرف من أبجدية بدون أحرف ملتبسة.
- أحادي الاستخدام، وصالح 24 ساعة.
- مربوط بالفرع والحملة.
- يُستهلك ذريًا في `submitInvoiceCode`.

## 8. لوحة الشركاء (ويب)

| الدور | الصلاحيات |
|---|---|
| `usersx_admin` | كل شيء، بما فيها إنشاء العلامات وإدارة المحتوى ونتائج المباريات |
| `partner_admin` | حملات علامته، وفروعها، ومناطقها، ومخزونها، وتقاريرها المجمعة |
| `branch_staff` | «شاشة الفرع» لفرعه، و«وضع الموظف»: مسح الاسترداد بكاميرا المتصفح، وتوليد رموز الفاتورة |

**التطبيق:**
- الأدوار مطالبات مخصصة (Custom Claims) في Firebase Auth، والدخول بالبريد وكلمة مرور مع التحقق الثنائي للمسؤولين.
- كل القراءة والكتابة عبر Callable Functions، فما فيه وصول مباشر من اللوحة لـ Firestore.

**قاعدة الخصوصية في التقارير:**
- الشريك يشوف مؤشرات مجمعة لكل فرع ويوم فقط.
- أي خانة أقل من 10 لاعبين تظهر «أقل من 10».
- ما فيه أي معرّف لاعب ولا إحداثيات.

## 9. الأمان (Firestore Security Rules)

- **قراءة اللاعب:** مستنداته فقط، والمحتوى العام (المنتخبات، والملاعب، والمباريات)، والغرف اللي هو عضو فيها.
- **كتابة اللاعب المباشرة:** فقط حقل `lastSeen` في مستند حضوره داخل الغرفة، بطابع وقت الخادم.
- **ممنوع على العميل كليًا:** الكتابة على المحافظ، والقسائم، والمخزون، والزيارات، والحملات، والجولات.
- **إخفاء بيانات اللغز:** بيانات اللغز الكاملة وحل الجولة في مستند خاص بالخادم. وكل لاعب يقرأ مستند «منظوره» فقط (`rooms/{id}/views/{uid}`).

## 10. الأحداث التحليلية

1. العميل يجمع الأحداث ويرسلها لـ `logEvents` كل 30 ثانية أو عند الخروج للخلفية.
2. الأحداث الحساسة تكتبها الدوال نفسها لحظة وقوعها، وما يُعتمد فيها على العميل: `branch_visit_verified` و`coupon_redeemed` و`co_op_win`.
3. التخزين في `events` مع حذف تلقائي (TTL) بعد 13 شهرًا.
4. `aggregateDaily` تحسب `metricsDaily` لكل فرع وحملة ويوم.

## 11. التكلفة والمراقبة

- تنبيهات ميزانية على مشروع `fq-prod` عند 50% و80% و100% من السقف الشهري المحدد.
- تقليل القراءات:
  - المحتوى العام مخزن مؤقتًا في العميل لمدة 24 ساعة.
  - مستمعو الغرف يعملون فقط والجولة مفتوحة.
- **مراقبة:**
  - معدل أخطاء الدوال.
  - زمن `redeemCoupon` (المستهدف p95 ≤ 800 مللي ثانية).
  - تعارضات المعاملات على مخزون الفروع.
